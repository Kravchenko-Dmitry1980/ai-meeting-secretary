# T8: голосовые и свободные текстовые команды

Статус: `IMPLEMENTED_OFFLINE`. Выполнены контрактные и синтетические проверки; качество русского STT/intent остаётся `NOT_QUALIFIED`. Реальные MAX native voice, CDN, Polza receipts, телефоны и сетевой маршрут не проверялись. Runtime factory с рабочими MAX/Polza credentials не включён: его подключение и эксплуатационные проверки относятся к T12.

## Граница сервиса

`VoiceCommandService(team, bot, voices, media, polza, *, clock=None)` принимает только уже привязанный к текущему участнику `BotEvent`. `enqueue(event, text=None, *, context=None)` сохраняет локальную очередь и возвращает «Обрабатываю…». Облачная работа выполняется отдельно: `await execute(claim, cancelled=...)`. Встроенные команды, списки задач и кнопки работают без AI. Свободный текст и голос используют платные запросы Polza; исчерпание общего бюджета останавливает новые запросы этих двух видов.

Автор определяется привязкой аккаунта MAX, revision и scope, без voiceprint. Перед загрузкой и каждым новым платным POST проверяются текущие права и fenced lease. Media adapter ограничивает источник 10 MiB и 120 секундами, нормализует на CPU, скрывает signed URL. Успешные файлы сохраняются adapter на 24 часа; приложение не удаляет их в `finally`. Очистка незавершённой загрузки принадлежит adapter. При отмене приложение дожидается завершения собственного media thread.

Polza вызывает `before_submission` после резерва T2 и до отметки отправки; приложение сохраняет request checkpoint. `response_checkpoint` сохраняет ограниченный сырой JSON, HTTP status и receipt после учёта денег, до parsing. Расшифровка сохраняется до intent. Исходный `allowed_context` сохраняется неизменяемым до первого intent POST: повтор старого ответа не получает новые версии задач/участников. Для replay используется только HTTP 200; сохранённые 201/202/5xx остаются `uncertain`, достоверные 4xx отклоняются без повторного POST. Известный STT response восстанавливается без загрузки/чтения временного WAV. Неизвестный оплачиваемый результат не повторяется.

Один месячный ledger T2 применяется к каждому POST, включая единственный разрешённый repair. Общий согласованный cap — 3 000 ₽, отдельной квоты на голос нет. Бюджет и настройки не меняются в этом сервисе.

T13 добавляет отдельный `not_submitted_checkpoint` и additive Team schema 9: если окончательная проверка бюджета отказала после request checkpoint, Polza сохраняет локальный immutable исход «не отправлено» только после успешного освобождения неотправленного резерва и до обращения к transport. Он связан с operation/stage/attempt/hash и не является HTTP-ответом провайдера. Команда получает `paused_budget` либо `paused_config`; тот же attempt автоматически не повторяется. При сбое записи этого исхода, отмене в этом промежутке или реальной неопределённой отправке остаётся `uncertain`. Старые pending requests при миграции не объявляются неотправленными; восстановление schema 7/8 до миграции сохраняет этот же консервативный контракт. Подробности и актуальный полный прогон — [TEAM_VALIDATION.md](TEAM_VALIDATION.md).

## Проверка и подтверждение предложений

Модель возвращает только `RawIntentReply`, максимум пять предложений. Foreign project/task/member ID отклоняется целиком и не исправляется запросом к модели. Literal evidence обязана быть подстрокой расшифровки. Локальные проверки отрицания, обсуждений, цитат, вопросов, гипотез и отозванного поручения дополнительно защищают от ошибочного model `utterance_kind=command`.

Исполнитель определяется только по уникальному точному имени/UUID из сохранённого разрешённого справочника. Явные самостоятельные «мне», «меня», «я» означают исключительно автора сообщения; противоречащий model member ID отклоняется. Отсутствующее упоминание не назначает автора автоматически. Неизвестные формы имени, например склонённое имя без точного совпадения, и неоднозначные одноимённые участники требуют новой уточнённой команды; fuzzy aliases не используются. Обычному участнику передаётся только его собственная запись справочника; owner получает ограниченный справочник своих проектов.

Отсутствие/неоднозначность исполнителя, проекта, задачи, даты или времени создаёт preview с `unresolved_fields`, без кнопки подтверждения. Единственный scope позволяет default project. Неявная задача не выбирается произвольно из доступного списка. Название новой задачи и изменяемые literal текстовые значения проверяются по исходному тексту.

Даты рассчитываются относительно timestamp исходного события в `Europe/Moscow`, а не текущего времени сервера. Поддержаны явные ISO даты/offset, русская дата с годом, сегодня/завтра/послезавтра и день недели с `HH:mm`. Отсутствующий час не превращается в 18:00. Противоречивые дата/день недели либо model date требуют уточнения. `propose_due` после кнопки «Предложить срок» дополнительно связан с durable `BotAction due`, исходной задачей/revision/fingerprint; такой контекст не разрешает другие действия.

IDs предложений и операций детерминированы от event/index/SHA256 исходного текста. TTL preview — 24 часа. `confirm_intent(actor, proposal_id, expected_revision, operation_id)` обращается только к VoiceRepository/T4: повторно проверяются текущие права, срок preview, task/member revisions, immutable operation и receipt. Повторное подтверждение не вызывает AI. Завершение требует результата; важные и неклассифицированные задачи переходят на проверку по канонической политике.

В durable outbox записываются стадии «Расшифровываю аудио», «Разбираю поручение» и итог. Стадия не повторно планируется, если соответствующий provider response уже сохранён. Имена в итоговом сообщении берутся из исходного context, поэтому смена имени не меняет payload сохранённого уведомления при replay. Preview показывает точные значения классификации, комментария, результата и причины. Если полный текст превышает 4 000 символов, неизменяемые части по 3 500 символов отправляются перед итоговым сообщением с кнопками; per-event FIFO VoiceRepository гарантирует порядок. Кнопка содержит opaque payload с action `confirm_intent:<proposal UUID>:<revision>` и отдельным сохранённым operation UUID.

Отсутствующий CDN contract/MAX transport переводит job в `paused_config` с просьбой владельцу проверить подключение MAX. Недопустимые размер/длительность и нечитаемый формат сообщаются отдельно, без signed URL или provider details. Ошибки настройки/credentials Polza (401/403 и отклонённый fixed wire) дают `paused_config`; месячный cap и недостаток баланса (402) дают `paused_budget` с разными сообщениями; неоднозначный запрос остаётся `uncertain`. Отзыв прав сохраняет отказ/неопределённость через fenced internal port, даже если автор больше не может получить обычный статус.
