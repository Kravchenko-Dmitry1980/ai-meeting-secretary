# MAX: транспорт и текстовые команды, T7

Состояние: реализовано и проверено в изолированных offline fixtures. Рабочий
бот, внешний HTTPS и приложение на телефоне ещё не подключены. Secretary на
`127.0.0.1:8765` не становится публичным Team Gateway от наличия этих файлов.
Runtime wiring, конфигурация HTTPS и ручная приёмка относятся к T11–T13.

## Контракт приёма

`POST /hooks/max` принимает единственный `X-Max-Bot-Api-Secret`. Host должен
соответствовать настроенному HTTPS origin. Секрет проверяется **до чтения и
разбора тела**; browser cookie, Origin и CSRF для webhook не применяются.
Для остальных Team API действуют прежние session/Origin/CSRF проверки.

Размер тела ограничен 1 MiB. Невалидный JSON получает 400, превышение размера —
413, неизвестный/повторённый секрет — 401, отсутствующая конфигурация или
недоступное хранилище — 503. HTTP 200 означает, что событие сохранено или найден
его ранее сохранённый экземпляр; это не подтверждение исполнения команды.

Действующие message/callback идентифицируются provider MID/chat или callback ID
в namespace бота. Время повторной доставки не заменяет ID и не меняет исходное
время события. Изменённое содержание под тем же ID отвергается. Hash тела служит
только диагностикой карантина, а не ID действующей команды. Неизвестный отправитель
не получает доступ к задачам, загрузке media или Polza.

Приглашение связывает candidate MAX ID в одной транзакции с inbox. Его исходное
значение не сохраняется; членство появляется только после подтверждения владельца.
Из такого события допускается единственный фиксированный ответ об ожидании доступа.

## Команды

| Команда | Результат |
|---|---|
| «Мои задачи», «Сегодня», «Просрочено» | Ограниченная страница своих задач, кнопки действий и переход к следующей странице |
| «Открыть доску», «Открыть матрицу» | Native `open_app`, если задано зарегистрированное имя бота; иначе HTTPS ссылка |
| «Вход на компьютере» | Личный одноразовый код T6, действующий пять минут |
| «Помощь» | Перечень команд |
| «Принять», «В работе» | Предпросмотр изменения и отдельное подтверждение |
| «Готово» | Запрос буквального результата, затем предпросмотр; важная/неразобранная задача направляется на проверку |
| «Предложить срок» | Сохранённое предложение; естественная дата не становится дедлайном без разбора и подтверждения |
| Свободный текст | Неизменяемый черновик для T8; задачи автоматически не меняются |
| Аудио/вложение | Честное сообщение, что обработка подключается в T8; в T7 загрузка и STT не выполняются |

Фильтр «Сегодня» использует календарный день Москвы, «Просрочено» — точный
подтверждённый срок раньше текущего момента. Оперативная политика Moscow UTC+03:00
реализована без установки `tzdata`; исторические переходы DST не вычисляются.
Непроверенная следующая страница не выдаётся за отсутствие задач.

Кнопка содержит непрозрачный nonce. На сервере сохранены actor, scope, revision,
fingerprint задачи, действие и срок действия. Профильное имя MAX и изменяемый
текст callback не дают права изменить задачу. Ответы всегда направляются в личный
диалог по точному MAX user ID, поэтому ID исходного группового чата не служит
доказательством права нажать кнопку. Nullable callback.message не отменяет
проверку пользователя и сохранённой кнопки.

`queued` означает принятую в очередь команду; `applied` — подтверждённое исполнение
T4; `conflict` требует нового актуального предпросмотра; `uncertain` требует
проверки результата и не запускает повторную mutation. Повтор подтверждения
возвращает квитанцию того же operation ID. Изменение actor/scope отзывает прежние
кнопки. Истёкшая неиспользованная кнопка не выполняется. Тот же уже принятый
callback после сбоя восстанавливает квитанцию и по истечении срока: immutable
confirmation checkpoint записывается атомарно с acceptance. Новый expired
callback не получает такого исключения.

## Доставка и восстановление

Team SQLite schema 4 содержит отдельные durable inbox, buttons, proposals,
contexts и outbox. Локальная обработка после потери lease восстанавливается по
сохранённым operation IDs и checkpoint. Перед MAX POST фиксируется `sending`;
потерянное подтверждение или истёкший sending lease становится `uncertain`.

HTTP 429 имеет отдельную ограниченную политику локального повторения: не более
трёх попыток обычного сообщения с задержкой. Это не remote idempotency guarantee.
Для кода входа повторная генерация/отправка автоматически запрещена даже после
429. Пользователь запрашивает новый код новым сообщением. Код создаётся только
после durable sending и остаётся в памяти отправителя; в SQLite сохраняется
только хеш T6, а в outbox — инструкция без значения кода.

`sent` подтверждает принятие сообщения MAX API, а не его прочтение человеком.
Регистрация подписки делает один POST для собственного URL и последующий GET.
Чужие подписки не удаляются. GET не возвращает webhook secret: совпадение URL
и update_types подтверждает маршрут, но не доставку с нужным секретом.

## Проверки и будущий live probe

Актуальные результаты и evidence — `docs/TEAM_IMPLEMENTATION_STATUS.md`.
Локальные проверки используют `scripts/run_offline_tests.py`, synthetic users,
temporary DB, MockTransport и ASGI без открытия socket. Они не подтверждают
работу реального MAX, телефона или внешнего маршрута.

После T11/T12 проверить на настоящем телефоне по отдельности:

1. Приглашение и подтверждение каждого участника, отказ неизвестному отправителю.
2. Текстовые команды, callback → preview → confirm → свежая квитанция T4.
3. Код входа и повторное использование/истечение пяти минут.
4. Native `open_app` с зарегистрированным public bot name и привязанным HTTPS URL;
   отдельно проверить обычную ссылку и desktop login.
5. Native voice и отдельно отправленный audio file: оба маршрута должны вернуть
   документированный media payload; успешный файл не квалифицирует native voice.
6. Перезапуск после приёма события и после отправки; никакого повторного изменения
   или бесконечного повторения сообщения с неизвестным результатом.

Перед этим выяснить у провайдера/router наличие доступного публичного адреса,
статического IP/CGNAT и выбрать домен. Сейчас эти сведения UNKNOWN. Настроить
MAX business для ИП, bot token и webhook secret локально по T11/T12. Секреты не
вводить в чат, не помещать в Git и не показывать в captured output.
