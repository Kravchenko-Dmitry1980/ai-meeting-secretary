# Ограниченный benchmark

Без API-ключа cloud-качество, задержка и цена остаются «не измерено». Mock-тесты проверяют runner и контракты, а не качество модели.

Следующая команда не обращается к API и создаёт локальный отчёт с `sample_count=0`, `p50=null`, `p95=null`, `confirmed_rub_per_hour=null`:

```powershell
& 'D:\AI\Projects\Active\Secretary\.venv\Scripts\python.exe' 'D:\AI\Projects\Active\Secretary\scripts\benchmark.py' --output 'D:\AI\Projects\Active\Secretary\.runtime\benchmark\offline.json'
```

После настройки локального backend-ключа и проверки эталонной короткой русской записи можно **явно разрешить один** запуск. Эта команда пока не выполнялась с настоящим облачным провайдером:

```powershell
& 'D:\AI\Projects\Active\Secretary\.venv\Scripts\python.exe' 'D:\AI\Projects\Active\Secretary\scripts\benchmark.py' --run-cloud --audio 'D:\path\test.wav' --reference 'D:\path\reference.txt' --max-rub 5 --output 'D:\AI\Projects\Active\Secretary\.runtime\benchmark\report.json'
```

Для альтернативного порта добавьте `--url http://127.0.0.1:8766`. `--critical-terms` принимает путь к UTF-8 JSON-массиву строк: термины, имена, числа, даты, отрицания. Источники не изменяются. Ключ никогда не передаётся скрипту, читается только признак `key_configured` локального API.

Runner требует простаивающий Secretary: реальные capture states проверяются через `/api/v1/meetings/{id}/recording`, jobs — через `/jobs`. Модели и все тарифы должны быть настроены, существующие неопределённые/зарезервированные расходы — сверены. Без этих условий нет import/submit и изменения конфигурации. Во время запуска не создавайте параллельные операции в UI: глобальная конфигурация однопользовательского приложения временно устанавливается на `--max-rub`, unknown price запрещается. Атомарной блокировки параллельных изменений пользователем у V1 нет.

`--max-rub` ограничивает локальные резервы и уже подтверждённые расходы одной benchmark-встречи; provider adapters дополнительно передают документированные тарифные caps. Фактическое применение caps и тарифы аккаунта ещё не измерены. Один запуск не пересоздаёт встречу, не повторяет импорт и не повторяет неопределённый оплачиваемый submit.

При завершении без активных jobs и неизвестных расходов прежние три поля конфигурации восстанавливаются. При сбое сначала запрещаются новые cloud calls, затем отменяются только jobs созданной benchmark-встречи. Если in-flight job или расход остаётся неопределённым, runner **сохраняет меньший лимит и отключённое облако**, когда API позволяет это подтвердить; больший прежний лимит не восстанавливает. Отчёт содержит `config_restored=false`, `cloud_pause_confirmed`, `prior_config`, `cleanup_note`. Проверьте сохранённые jobs/квитанции и восстановите поля через настройки после сверки. Не повторяйте benchmark вместо восстановления существующего результата.

Отчёт содержит реальные jobs, статус HTTP саммари (202 означает неготовый результат), source-linked summary, время до первого текста, общее время, usage, длительность аудио и WER/CER при эталоне. Нулевая/пустая расшифровка может быть настоящим ответом; она не заменяется демо. Пустые задачи допустимы. Расход за час вычисляется только по подтверждённым квитанциям без pending/unknown; иначе `null`.

Один sample не даёт p50/p95. Для описательных процентов нужны повторные независимо ограниченные измерения; оценка хвоста требует большего набора. Имена, технологии, даты, числа, отрицания, решения и задачи проверяются по исходной записи и ссылкам вручную. Автоматический поиск exact terms — вспомогательная проверка, не доказательство правильных договорённостей.

RAM/CPU относятся к **самому backend процессу**, без браузера, FFmpeg и облачных серверов. RSS — максимум наблюдённых значений при опросе каждые 0.5 секунды; короткие всплески могут не попасть в измерение. Первое появление текста также наблюдается опросом и имеет соответствующую погрешность. PID берётся из `.runtime/processes.json` только при совпадении порта, проекта, launcher и времени создания; PID другого или завершившегося процесса не используется. Недоступные метрики — `null`. Стоимость полного конвейера за час не рассчитывается при частичной обработке.

Exit codes: `0` — dry-run или завершённая обработка; `1` — частичный результат/сбой; `2` — входные параметры или preflight отклонили запуск. Новый JSON-отчёт сохраняется также при отклонении и обработанном сбое, чтобы прежний успешный отчёт не выдавался за текущий.
