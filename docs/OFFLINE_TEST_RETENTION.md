# Хранение временных данных offline-тестов

`scripts/run_offline_tests.py` запускает pytest в отдельном процессе и сохраняет
короткий `retention-summary.json` и, по умолчанию, `junit.xml` в корне каждого
нового `.runtime/team-rollout/offline-<32 hex>/`.

После завершения pytest очищается **только `pytest-temp`** успешного прогона.
Для неуспешных и прерванных прогонов сохраняется не более **трёх** каталогов
`pytest-temp` общим логическим объёмом не более **4 ГиБ**, начиная с новейших.
Один неуспешный каталог свыше 4 ГиБ также удаляется; отчёт и код завершения
сохраняются. Лимит относится к завершённым временным данным, а не к объёму
активно выполняющегося теста. Сам запуск большого набора ещё может требовать
нескольких гигабайт свободного места.

Автоматическая очистка действует только на новые прогоны с маркером
`secretary-offline-retention-v1`. Старые немаркированные UUID-каталоги не
подхватываются. Корень прогона, `child-guard`, `node-cache`, отчёты, сторонние
подкаталоги `.runtime`, данные встреч и рабочие окружения не удаляются.

Защита от параллельных запусков использует файловые блокировки ОС для
supervisor, pytest-worker и самой очистки. PID вместе со временем создания
позволяет сохранить временные данные ещё работающих дочерних процессов.
Если runner аварийно завершился, его свободный от процессов каталог считается
прерванным. Проверка пути запрещает reparse points в границе удаления;
внутренние junction/symlink удаляются как ссылки без обхода цели. Это защита
от случайных эффектов доверенных тестов, не sandbox для враждебного процесса.

Ошибка очистки видна в stderr и `retention-summary.json`; после успешных тестов
runner возвращает код 3, если очистку выполнить не удалось. Исходный ненулевой
код pytest сохраняется. Занятые активными процессами каталоги остаются на месте
и перепроверяются после следующего offline-прогона. Ничего не удаляется по
таймеру в фоне.

Явный `--junitxml=<path>` сохраняет заданный вызывающим кодом путь отчёта.
Путь внутри `offline-<id>/pytest-temp` отклоняется до запуска тестов, чтобы
очистка не уничтожила отчёт. При отсутствии этой опции используется
`offline-<id>/junit.xml`. Вывод pytest продолжает идти в stdout/stderr, поэтому
существующие перенаправления в отдельные журналы сохраняют своё поведение.

Узкая регрессионная проверка (запускается без сети и реальных данных):

```powershell
& .\.venv\Scripts\python.exe -B scripts/run_offline_tests.py tests/test_offline_test_retention.py tests/test_team_preflight.py tests/test_offline_sqlite_uri.py -q
```

Она проверяет исходное накопление успешных прогонов, лимиты неудачных,
сохранение отчётов, защиту живых процессов, строгую границу пути, junction,
повтор после ошибки удаления и сохранение действующих offline-ограничений.
