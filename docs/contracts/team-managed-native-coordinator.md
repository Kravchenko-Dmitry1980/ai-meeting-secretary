# Полный диагностический цикл native Vikunja

2026-10-05. Реализуется внутренняя R4 lane из [native-read contract](team-native-read-observation.md). Ни один результат этого цикла не является разрешением activation/outbound.

Входы — явные существующие project/backup/restore/maintenance/lifecycle/runtime-config paths. Production entrypoint сам собирает `SourceEvidence`, текущие settings, bot token binding и отдельную SQL-проекцию human owner. `TokenEvidence.owner_id` — bot principal; UUID local owner не используется как native ID. Binary фиксирован на Vikunja 2.7.0 с известным SHA. Caller не предоставляет transport, clock, launcher или proof.

Непрерывность: пока начальный stopped collector открыт, coordinator дублирует точные files/directories leases и получает native NoWrite. После повторной проверки collector закрывается. Только native переключается с перекрытием HANDLE в NoDelete. Остальные SQL/archive/assets/control/config/binary остаются удержанными. Завершающий stopped collector открывается после exact stop и возвращения native NoWrite, под теми же внешними leases; его snapshot сравнивается с исходным. Не добавляется `allow_running`.

Один disposable CLI worker удерживает исходный Popen HANDLE, новый actual Windows Job и конечный бюджет полного process lifecycle. Marker предотвращает случайный вызов из обычного сервера, но не аутентифицирует процесс. Проверяются creation identity, membership/accounting и точный IPv4 listener `127.0.0.1:port`. GET transport выполняет уже проверенные fixed routes. Неизвестный lifetime, потеря identity или timeout остаются FAIL. Cleanup всегда останавливает только известного созданного ребёнка, по исходному HANDLE; проверяются signal/reap/readers/root-only. Terminal exit 259 определяется signal, а не значением exit code.

Отдельный журнал `restore_managed_native_observation` атомарно потребляет свежее operator approval и записывает started attempt до Popen. Повтор nonce/approval и незавершённая предыдущая попытка запрещены. После crash нужен новый stopped reconciliation. Failure можно записать после expiry; успешное завершение требует действующего approval. Journal не меняет provider observations, billing или restored sources.

Сначала sidecars, затем native bytes/FileID; затем полный fresh readback всех четырёх источников, metadata/390 fences/42 tables/rowids/head/events/grants. Любой journal либо изменение — `native_readonly_get_unreconciled`. Нет checkpoint, удаления journals, миграций, repair или fallback RW. Успешный sanitized terminal сохраняется после закрытия owned source custody; ошибка journal write не превращается в success.

Terminal относится к завершённому историческому cutoff удержания inputs, а не к текущим правам после их освобождения: `closed_observation_only=True`. Последующая аутентификация проверяет только подпись/operator/expiry approval. Rotation после cutoff не делает историческое наблюдение разрешением запуска. При недоказанном process cleanup worker вызывает `os._exit(70)` до обычного unwind источников; kill-on-close Job и HANDLE закрываются при его смерти. Started journal остаётся незавершённым; это crash outcome, не closed PASS.

Приёмка: tests переходов полного цикла и всех отказов, durable consume-once/terminal/schema/hash/rollback, actual Win32 file locks и private synthetic process faults. Synthetic receipts всегда явно synthetic. Следующая actual pinned-binary проверка должна использовать новый изолированный fixture; offline PASS не заменяет native API proof, browser/phone/manual или production activation. Directory helper dependencies, transitive binary effects и mapped image correspondence не получают выдуманных гарантий.
