# T10: отправка напоминаний

Код T10 не включает runtime factories. До T12 импорт модулей ничего не запускает.
Проверки используют синтетические Team DB и HTTPX MockTransport. Они не доказывают
доставку на реальный телефон, прочтение или работу производственного MAX webhook.

## Контракт

`NotificationSender(team, canonical_clients, max_client, *, clock=None,
budget_reader=None)` получает карту доверенных `project_id -> VikunjaClient`.
`dispatch(intent, *, authorize, before_send, cancelled=None) -> SendReceipt`
требует два callback: текущую `NotificationAuthorization` и атомарную фиксацию
отправки. Самостоятельной отправки без durable outbox нет.

`NotificationWorker(repository, sender, *, worker_id, lease_seconds=60,
poll_seconds=1.0)` предоставляет асинхронные `run_once()` и `run()`, а также
`stop()`. `run_once()` возвращает сохранённый `SendReceipt` либо `None`.
Планирование отдельно: полный подтверждённый снимок → `ReminderScheduler.plan`
→ `NotificationRepository.commit_plan`. Worker обрабатывает только уже
сохранённые intents; он не объявляет набор задач полной актуальной сводкой.

Порядок одной попытки:

1. Восстановить истёкшие leases, взять один intent и запустить heartbeat.
2. Проверить текущее членство, revision, MAX/Vikunja binding и права проекта.
3. Для каждой выбранной задачи выполнить безусловный GET через VikunjaClient.
   Сравнить результат с текущей локальной проекцией. Внешний неподтверждённый
   срок или несинхронизированное изменение откладывают отправку.
4. Повторно проверить локальные права и проекции, сформировать новый текст.
5. `mark_sending(claim, send, observed_fingerprints=...)` в одной транзакции
   проверяет fence, права, поколения сроков и fingerprints, сохраняет точный
   `BotSend` данной попытки, увеличивает attempt и выставляет `sending`.
6. Выполнить один приватный MAX POST; сохранить его отдельный receipt.

Текст `intent.text` — только preview и никогда не становится MAX body.
Отправляются текущие названия задач, точные ID и подтверждённые сроки с МСК.
Одна часть содержит максимум 10 задач, строка задачи ограничена 250 символами,
сообщение — 3500. Каждая часть имеет отдельные durable ID и результат.

## Изменения, ночь и повторные попытки

Сводка исключает закрытые задачи и ссылки с изменившимся поколением срока или
исполнителем. Если не осталось ни одной задачи, intent отменяется. При частичном
изменении стабильная часть не пересобирается: исключённая задача может появиться
в следующей сводке в 09:00. Индивидуальное устаревшее напоминание отменяется.
Название можно обновить без смены поколения срока после проверенной синхронизации.

В 21:00–09:00 МСК proactive сообщения откладываются; пользовательский BotOutbox
этим ограничением не затронут. Вчерашние task intents утром отменяются, новая
сводка имеет отдельный ID. Отмена накопленного backlog при запуске, восстановлении
и длительном перерыве находится в `commit_plan`; sender дополнительно запрещает
отправлять task intent за предыдущую московскую дату.

Только доказанный MAX 429 с `Retry-After` допускает новую попытку, максимум три.
Каждая такая попытка заново проверяет задачи и фиксирует свой актуальный текст.
Timeout, неизвестный ответ, потеря lease после начала POST и неопределённый успех
дают `uncertain`: автоматической повторной отправки нет.

Остановка/отмена до `mark_sending` не отправляет сообщение. После успешного
`mark_sending` попытка принадлежит worker: отмена дожидается завершения потока и
сохранения результата. Повторная отмена не отделяет работающий поток; замещающий
`run_once()` ждёт тот же lock. Потерянный fence не может записать ложный `sent`.

## Бюджет и доказательства

Только бюджетные предупреждения требуют свежего локального `BudgetSnapshot`.
Проверяется текущий период (смена месяца в 01:00 МСК), положительный эффективный
лимит не выше согласованного и 3000 рублей, а также порог по подтверждённым
расходам плюс резервам. Провайдер не вызывается для проверки бюджета. Отсутствие
актуального доказательства или падение ниже порога после снятия резерва откладывает
тот же immutable intent на 60 секунд; позднейшее достижение порога не теряется.
Intent за завершившийся billing period отменяется как устаревший. Отсутствие
Polza/бюджетного снимка не блокирует обычные напоминания. В сообщение о бюджете
попадают период и достигнутый порог, без суммы из старого preview.

`sent` означает проверенное принятие MAX API. `accepted_at`, если присутствует,
получен из фактического provider `message.timestamp`; локальное время его не
заменяет. Полей или утверждений о прочтении пользователем нет.

Сфокусированная проверка без сети:

```powershell
.venv\Scripts\python.exe -B scripts\run_offline_tests.py tests\test_notification_sender.py tests\test_notification_worker.py -q --tb=short
```
