# Панель владельца команды

Панель показывает локально сохраненные факты для выбранного проекта. Доступ есть только у действующего владельца, которому разрешен этот проект. Смена роли, отключение участника или смена его ревизии во время чтения запрещают выдачу всего ответа.

`GET /api/team/v1/dashboard?project_id=7&limit=50` использует тот же защищенный сеанс, что доска и матрица. Максимум страницы — 100 команд. `commands.next_cursor` передается в `after` без преобразования; курсор привязан к проекту. Команды упорядочены от наиболее раннего приема к более позднему с дополнительной сортировкой по UUID.

В `commands` находятся только `queued`, `running`, `reconciling`, `uncertain`. Панель показывает UUID операции, ID задачи, действие, состояние, время приема, последнего изменения состояния, срок аренды исполнителя и безопасный код ошибки. Принятая команда еще не подтверждает изменение задачи в Vikunja. Примененные и отклоненные операции остаются в истории задачи.

Статистика `deliveries` объединяет явно подключенные локальные хранилища ответов бота и голосовых предложений. Статистика `notifications` приходит из отдельного локального хранилища напоминаний. Состояние `observed` означает, что локальные записи успешно прочитаны. `issues` означает наличие неопределенных или отклоненных отправок; оно не доказывает текущее состояние сети. `not_configured` означает отсутствие подключенного источника, `unavailable` — невозможность получить достоверную сводку. В последних двух случаях счетчики равны `null`; реальный ноль появляется только после чтения источника.

`max_api_accepted_count` и `last_max_api_accepted_at` означают принятие сообщения API MAX. Время берется только из проверенной сохраненной квитанции `SendReceipt.accepted_at`, которая содержит исходный `message.timestamp` MAX. Старые квитанции без этого поля сохраняют неизвестное время. Время входящего события, аренды исполнителя и локальных часов не подменяет время MAX. `human_read_confirmed` всегда `null`: API-квитанция не подтверждает доставку на устройство или прочтение человеком.

Ответы общего назначения приписываются проекту только при единственном проекте в сохраненном контексте входящего события. Для ответов со ссылкой на команду используется ее канонический проект и соответствие автора события автору команды. Общие ответы участника с несколькими проектами исключаются из проектной сводки. Это предотвращает смешивание отправок разных проектов, но сводка не заменяет общий журнал всех сообщений.

`webhook` по умолчанию имеет `not_configured`. Обычная запись в inbox не доказывает прохождение аутентификации HTTP webhook. Только явно подключенный доверенный локальный читатель может сообщить `last_authenticated_accept_at`; его состояние остается `unknown`, поскольку прошлый прием не подтверждает текущую доступность внешнего адреса. В этой реализации не добавлен журнал аутентифицированных webhook или внешняя проверка доступности.

`status` переиспользует сводку синхронизации и бюджета. Последняя проверка команды и последний успешный полный опрос Vikunja — разные поля. Бюджет читается из локального месячного реестра; открытие панели не отправляет запросы в Polza и не расходует бюджет. Суммы передаются точными десятичными строками.

Ответ не содержит текстов сообщений, голосовых команд, исходных webhook, цитат встреч, MAX ID пользователей, ID исполнителей фоновых процессов или секретов. Браузер проверяет схему, идентификаторы, даты, границы страницы и значения неизвестной статистики. `403` не завершает сеанс участника, а `503` не превращается в демонстрационный успех.

Проверки выполнялись на временных базах с синтетическими участниками и квитанциями, без сети. Подключение рабочих портов, реальный webhook, отправка на телефон и ручная приемка относятся к следующим этапам; зеленые локальные проверки не подтверждают их готовность.
