# Детерминированные команды MAX (T7)

`BotCommandService(team, bot, *, public_origin, bot_username=None, clock=None)` принимает только нормализованный, сохранённый `BotEvent`. Он не выполняет HTTP-запросы и не вызывает Polza или другие модели. Транспорт и worker подключаются отдельно.

Перед обработкой сервис сверяет текущие `TeamMember.id`, `enabled`, точный `max_user_id`, `revision` и полный набор проектов с сохранённой привязкой события. Неизвестный кандидат приглашения получает только фиксированный ответ об ожидании владельца. Отправка ответа происходит лично пользователю: исходный групповой chat и callback без chat не меняют его права.

| Команда | Поведение |
| --- | --- |
| Мои задачи | Незакрытые задачи участника, пять проверяемых карточек на страницу, переход между разрешёнными проектами. |
| Сегодня | Подтверждённые сроки на текущую московскую дату в пределах страницы. |
| Просрочено | Подтверждённый `due_at` раньше текущего момента; закрытые задачи исключены. |
| Открыть доску / Открыть матрицу | При явно настроенном `bot_username` — нативная `open_app` с payload `board` / `matrix`. Иначе — честно обозначенная HTTPS-ссылка `/team/?view=...`. Сам интерфейс относится к T9. |
| Вход на компьютере | Только инструкция `sensitive_action='desktop_code'`. Код создаёт отдельный worker после начала доставки; код не входит в сохраняемый reply. |
| Помощь | Список команд и правила подтверждения. |

Фильтры проверяют ограниченную страницу источника, поэтому пустая отфильтрованная страница не означает отсутствие задач на следующих страницах. Cursor указывает на последнюю проверенную карточку, дополнительный `N+1` элемент не пропускается. Сервис использует оперативную политику Moscow UTC+03:00 без зависимости от системной базы tzdata; исторические изменения московского часового пояса здесь не рассчитываются.

«Принять» и «В работе» создают `CommandPreview`; кнопка «Подтвердить» содержит только opaque nonce сохранённой команды. `operation_id` определяется событием, действием и задачей. Идентификаторы, ревизия и fingerprint берутся из серверной привязки кнопки. Смена карточки между чтениями отклоняется. Принятие команды и подтверждение nonce выполняет repository атомарно.

«Готово» сначала запрашивает результат. Контекст задачи сохраняет исходную ревизию и fingerprint; следующее непустое текстовое сообщение привязывается к этому контексту идемпотентно. Результат сохраняется буквально. Подтверждённая обычная задача переходит в `done`, важная или неклассифицированная — в `review`; оба действия требуют отдельного подтверждения. Полный текст результата сохраняется даже при сокращённом отображении preview.

«Предложить срок» сохраняет следующий текст как предложение без изменения срока. Остальной свободный текст также остаётся предложением, задача автоматически не создаётся. Разбор естественных дат, свободного текста и аудио относится к T8. Сообщения с вложениями получают указание отправить текст; модель и транскрибация не запускаются. Встроенные команды распознаются раньше ожидаемого результата или срока и не расходуют этот контекст.

Ответы различают `queued`, `running`, `reconciling`, `applied`, `conflict`, `uncertain` и `rejected`. «Проверить статус» читает receipt; оно не повторяет мутацию. Только `applied` означает подтверждённое изменение карточки. Проверки T7 используют временные синтетические базы и локальные порты, без фактической доставки MAX.

Сфокусированная проверка:

```powershell
.\.venv\Scripts\python.exe -B scripts/run_offline_tests.py tests/test_bot_commands.py -q --tb=short
```
