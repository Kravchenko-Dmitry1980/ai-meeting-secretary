# Secretary: участники, голоса и ответственные за задачи

Дата: 2026-10-02. Статус: проект решения для реализации моделью **Sol 6.1 (`gpt-6.1-sol`)**. Изменения продукта и платные запросы в рамках подготовки этого документа не выполнялись.

## Задача пользователя

Совещание проходит **в одной комнате с общим микрофоном**. Обычно участвуют пользователь («Я», настоящее отображаемое имя задаётся в интерфейсе), Павел Александрович и Алексей; иногда присутствует один приглашённый специалист. Требуется различать реплики, узнавать постоянных участников и корректно определять исполнителя задачи.

Голосовой профиль хранит подтверждённые образцы речи и признаки для сравнения. Синтез/клонирование голоса не требуется. Канал `microphone` не определяет личность говорящего. Число известных профилей не означает, что все эти люди обязательно говорили на конкретной встрече.

## Факты текущего приложения

- Рабочая модель на момент проверки: `openai/whisper-large-v3-turbo`, фрагмент 120 секунд. Автоматического распознавания личности нет.
- Адаптер принимает `segments[].speaker`, если модель его вернула: `backend/secretary/infrastructure/polza.py:466`. Worker создаёт локальную метку для пары chunk/label: `backend/secretary/application/worker.py:464`.
- Таблица speakers не содержит версии расшифровки; API выдаёт список без фильтра версии. UI предупреждает «в пределах фрагмента»: `frontend/src/components/TranscriptView.tsx:29`.
- Summary получает `{id,text}`, теряя говорящего: `backend/secretary/infrastructure/polza.py:767`. `owner` является строкой, а два валидатора требуют буквального имени в источнике. Одного добавления подписей к репликам недостаточно для задачи «я сделаю».
- После предыдущего ремонта проверены 465 Python и 41 frontend-тест. Это историческая исходная точка; исполнитель перепроверяет её на своём checkout.

## Выбранная архитектура

Основной вариант: **Polza `aiesa/transcribe` → реплики с таймкодами и анонимными метками → локальное сравнение голосов → проверка участников → задачи с основанием назначения**.

Для локального сравнения кандидат — `speechbrain/spkrec-ecapa-voxceleb`: извлечение speaker embeddings, вход 16 kHz mono. Его точность в этой комнате не установлена; модель проходит отдельную проверку совместимости Windows/Python 3.12 и качества. Новую тяжёлую зависимость загрузить только в проектное дополнительное окружение, с закреплёнными версиями и ревизией весов. Если кандидат не подходит, оставлять рабочую ручную привязку реплик и явно сообщить, что автоматическое узнавание не квалифицировано; не подменять результат случайным совпадением.

Обработка сохраняется на диск во время записи. Локальный этап узнавания выполняется после завершения STT текущей версии; он не должен задерживать сохранение аудио и работу интерфейса. В первом выпуске не требуется показывать имена с минимальной задержкой во время живого разговора.

Альтернативный компактный маршрут через Polza с `known_speaker_names`/`known_speaker_references` разрешено выбрать только после подтверждения фактической доступности. Публичная документация описывает `gpt-4o-transcribe-diarize`, но свежие каталог/карточки не подтверждают эту модель. Не отправлять платные догадки по разным ID и не подключать другого поставщика/аккаунт без решения пользователя.

## Требования продукта

1. Экран «Участники»: профили трёх постоянных людей и их явно заданные варианты имени. Не создавать реальные профили незаметно при миграции. Участник встречи выбирается из профилей; гость может существовать только внутри встречи.
2. Мастер образца: человек говорит один 20–30 секунд в обычном положении относительно общего микрофона; пользователь прослушивает и подтверждает образец. Выделить до трёх чистых отрывков по 5–10 секунд, суммарно не менее 15 секунд речи. Недостаточный материал просить перезаписать. Это выбранный продуктовый минимум, а не обещание точности модели.
3. Перед сохранением образца — подтверждение участника на использование его голоса для узнавания. Образцы/embeddings хранятся локально, вне Git, браузерного localStorage и логов. Общий каталог API содержит только метаданные; воспроизведение идёт через защищённый локальный audio endpoint.
4. Профиль можно переименовать, отключить, заменить образцы и удалить образцы. Отзыв образца запрещает новые вычисления с ним; запущенный локальный job отменяется/помечается устаревшим. Удаление образцов не удаляет встречи и историю ручных назначений.
5. Один и тот же известный человек сохраняет постоянный `person_profile_id` между встречами. `meeting_participant_id` относится к одной встрече и одинаков для его реплик внутри неё; у гостя ссылка на постоянный профиль nullable. В API поле `participant_id` всегда означает `meeting_participant_id`. Анонимные `SPEAKER_01` разных чанков никогда не объединяются только по совпадению строки.
6. Гость, тишина, шум, короткая реплика, наложение и близкие scores дают «Не определён»/«Нужна проверка». Не принуждать голоса к одному из трёх профилей. Без точных интервалов реплики нельзя приписывать целиком двухминутный текст преобладающему голосу.
7. При автоматическом результате показывать имя как предложение. Пользователь может подтвердить участника, исправить всю группу в пределах данной версии либо только конкретную реплику. Не переносить ручное исправление безусловно на новую расшифровку.
8. Доступна быстрая проверка: три карточки предполагаемых участников с примерами речи, отдельная очередь спорных реплик и гостя. Подтверждение группы не скрывает сегменты, у которых есть конфликт или наложение.
9. Исправление имени/привязки не запускает повторный STT или новый платный summary. Локально пересчитать зависимые предложения ответственных; семантический пересмотр текста итогов — отдельное явное действие.
10. Задача имеет `participant_id`, способ назначения, источники, статус проверки и версию атрибуции. Старое поле `owner` сохраняется как совместимое отображаемое значение.

## Правила ответственного

| Источник | Предложение и условия подтверждения |
|---|---|
| Павел: «Я подготовлю отчёт» | Павел; личность говорящего должна быть подтверждена, а фраза — явным обязательством. |
| Алексей: «Павел Александрович подготовит отчёт» | Павел Александрович по явному имени, независимо от личности автора реплики. |
| «Алексей, подготовь смету» | Алексей как явно названный адресат поручения; не утверждать, что он согласился, если согласие не звучало. |
| «Я не буду делать отчёт» | Не создавать положительное обязательство этого человека. |
| «Павел сказал: “я подготовлю”» | Не назначать автору цитирующей реплики. Сохранить для проверки или опереться на явно названного Павла с пометкой передачи чужих слов. |
| «Мы сделаем», «кто-нибудь подготовит», «может, Алексей займётся?» | Исполнитель не подтверждён; предложение/вопрос не превращается в согласованное поручение. |
| Неизвестный гость: «Я сделаю» | Участник-гость только после подтверждения личности; до этого задача требует проверки. |

Валидная цитата и speaker ID подтверждают происхождение, но сами по себе не доказывают смысл обязательства. Первоначально задачи — черновик для подтверждения. Допускается быстрое подтверждение списка; рассылка задач во внешние системы не входит в выпуск.

## Данные и границы

Добавить сущности `PersonProfile`, `VoiceEnrollment`, `MeetingParticipant`, `AttributionRun`, `SpeakerAttribution`, `TaskAssignment`. Атрибуция ссылается на **meeting + transcript_version + segment_id**; group operations раскрываются в конкретные сегменты указанной версии. Исходные text, timing, channel и provider label сохраняются. Существующие исторические speakers не получают придуманные личности.

`AttributionRun` хранит хеш аудио, версии модели/профилей/алгоритма и ревизию ручных поправок. `SpeakerAttribution` хранит nullable participant, method, nullable raw score, status (`proposed`, `confirmed`, `unknown`, `conflict`), причины и revisions. Cosine score не показывать как процент вероятности. Поздний автоматический job не заменяет более свежую ручную правку.

`TaskAssignment` привязан к summary_version и action ID; содержит `named_person`, `self_commitment`, `manual` или `unknown`, дословную цитату и segment IDs. Пересозданные итоги требуют явного сопоставления старых ручных назначений; совпадения порядкового номера задачи недостаточно.

Ключи summary/checkpoints включают снимок атрибуции, его revision и roster_revision (имена, aliases, состав). Изменение имени/состава участников локально перепроверяет также `named_person`: появление второго Алексея может сделать назначение неоднозначным. Автоматическое назначение со сменившимся/неоднозначным исполнителем теряет подтверждение и становится needs_review; ручное назначение сохраняется с предупреждением о конфликте. Старые результаты сохраняются доступными; изменение привязки не делает их незаметно актуальными.

Сохранить исправленный контракт отмены/возобновления, `uncertain`, квитанции, реальные ограничения на размер данных и localhost-защиту. `local_cost_limits_enabled=false` остаётся false. Пользователь контролирует расходы в Polza с месячным пределом 1000 ₽; не вводить новые внутренние денежные блокировки или потолки тарифа.

## Приёмка

Автотесты подтверждают контракты/сбои. Качество проверяется отдельными реальными записями, не использованными для образцов: минимум две встречи суммарно от 15 минут, 150 размеченных реплик и 30 реплик приглашённого участника. Если материала меньше, обозначить пилот, не считать качество квалифицированным.

Предлагаемые критерии пилота: точность автоматически предложенных имён не менее 98% на пригодных для сопоставления репликах при покрытии не менее 80%; ни одного наблюдаемого отнесения гостя к постоянному участнику; DER не более 15% на неналоженной речи с collar 250 мс. Отдельно показать overlap, короткие реплики, sample sizes и доверительные интервалы. Эти числа — цели приёмки, не ожидаемая гарантия.

На размеченном наборе проверок задач — ноль ошибочно подтверждённых исполнителей, цитаты/ссылки существуют, отрицания и чужие цитаты не превращаются в личные обязательства. Не достигнут критерий — автоматические предложения остаются с ручной проверкой, факт отражается в отчёте.

## Источники и степень подтверждения

- [Polza Audio Transcriptions](https://polza.ai/docs/api-reference/audio/transcriptions): описаны diarized output и known-speaker параметры. Это документация, не доказательство доступности конкретной модели аккаунту.
- [Polza STT catalog](https://polza.ai/api/v1/models/catalog?type=stt&limit=100) и [карточка Aiesa](https://polza.ai/api/v1/models/aiesa/transcribe): GET 2026-10-02; в STT-каталоге 12 моделей, Aiesa присутствует. Полный `/api/v1/models` содержит 419 моделей. Карточки `openai/gpt-4o-transcribe-diarize`, `gpt-4o-transcribe-diarize`, `elevenlabs/speech-to-text` вернули 404.
- [Aiesa](https://polza.ai/docs/gaidy/aiesa-transcribe): асинхронная расшифровка с анонимными спикерами и таймкодами. Узнавание ваших людей требует дополнительного слоя.
- [OpenAI native speech-to-text](https://developers.openai.com/api/docs/guides/speech-to-text): до четырёх references по 2–10 секунд. Нативный контракт OpenAI не подменяет контракт Polza.
- [SpeechBrain model card](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb): speaker embeddings/verification, 16 kHz mono, Apache-2.0; точность на чужом benchmark не переносится на эту комнату.

Доступ в приватный dashboard/баланс аккаунта не проверялся, живых аудиозапросов не было. Все выборы модели заново проверяются перед реализацией интеграции.
