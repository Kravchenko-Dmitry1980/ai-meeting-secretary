## Контракт изменения

Пользователь запускает, отменяет и продолжает обработку локальной встречи. Готовые результаты и подтверждённые расходы сохраняются. «Продолжить» использует успешный результат текущей версии, включая пустую расшифровку. Новый оплачиваемый запрос допустим только для незавершённой работы с достоверно безопасным повтором либо явно начатой новой версии. Отмена до отправки предотвращает запрос; после отправки сохраняются результат и квитанция. Неопределённый результат принятого POST не даёт права повторной оплаты.

Ошибочные/слишком большие ответы провайдера получают понятную классификацию, а исправление итогов соблюдает размер исходного блока. Конфигурация отклоняет бесконечные числа и пустые model IDs при сохранении. Пропавшее аудио даёт понятную ошибку. OpenAPI отражает ожидание, аудио, события и экспорт.

Интерфейс не применяет источники старой встречи к новой, не подтверждает сохранение неотправленного черновика и не скрывает одну ошибку успехом другой операции. Настройки и поиск доступны на узком экране. Явный бюджет benchmark действует только в его собственном запуске с восстановлением прежней конфигурации.

## Приёмка

1. Штатный backend-набор, новые регрессии и 22 ранее падавших audit cases проходят без ослабления утверждений о результате.
2. Frontend tests, TypeScript, ESLint, сборка и типы OpenAPI проходят.
3. На отдельном синтетическом браузерном стенде проверяются отмена/продолжение и мобильный доступ; производственные данные не используются для изменяющих тестов.
4. Рабочее приложение перезапускается и доступно на 8765; количества пользовательских данных и финансовые настройки сверяются до/после.

Изменения касаются существующих дефектов. Интеграция сверки расходов с authenticated history, новая история таймингов и оценка качества моделей остаются отдельными будущими функциями. Настоящий микрофон/WASAPI требует отдельной проверки с устройствами.

## Что исправлено

| Группа | Результат и проверенная граница |
|---|---|
| Отмена → продолжение | Сохранённый STT-результат и receipt используются в той же версии без второго POST. Пустая успешная расшифровка тоже считается выполненной работой. |
| Отмена во время преобразования аудио | Повторная проверка перед отправкой предотвращает облачный запрос; неотправленный резерв освобождается. |
| Сбой между сохранением текста и фиксацией отмены | `succeeded + cancel_requested=1` требует явного продолжения. Другой завершённый фрагмент не запускает итоги автоматически; API-продолжение с `retry=False` не создаёт новую версию. |
| Сбой после успешного сохранения | Ошибка локального завершения/запуска следующего этапа не превращает полученный результат в безопасно повторяемый платный запрос. |
| Повреждённые и чрезмерные ответы | Ограничена потоковая загрузка и распаковка; патологические JSON-числа, глубина и Unicode получают typed error. Неопределённый принятый POST не отправляется заново. |
| Асинхронный контракт | HTTP 200 с terminal `failed` классифицируется как отказ. GET по сохранённому job ID проверяет совпадение ID; чужие результаты и receipts не принимаются. |
| Исправление итогов | Корректирующие запросы ограничивают исходные выдержки и общий размер запроса. Неподтверждённые пункты исключаются с явным счётчиком. |
| Данные расходов и диагностика | Поддержан RUB alias `usage.cost`, расширена безопасная классификация error codes/reasons. Некорректный явно указанный `cost_rub` не подменяется нулём или alias. |
| Валидация настроек | NaN/Infinity в тарифах и пустые/пробельные model IDs отклоняются до изменения сохранённой конфигурации. |
| Недоступный аудиофайл | Пропавший файл получает понятный 404; проверены отсутствие исходника и гонка исчезновения при чтении. |
| Контракт API | OpenAPI и TypeScript-типы описывают ожидание 202, готовые ответы, SSE, WAV Range и четыре формата экспорта. Схема работающего приложения совпадает с сохранённой. |
| Источник старой встречи | Запоздалые source responses, seek и ошибки воспроизведения не применяются к другой встрече или закрытому preview. |
| Save и refresh | Черновик, изменённый во время Save, сохраняется в форме и не получает ложное подтверждение. Успех одной параллельной операции не скрывает ошибку другой. Прямой двойной вызов action защищён синхронным guard. |
| Узкий экран | Поиск и вход в настройки доступны при ширине <=760 px; проверено в Chrome mobile emulation. |
| Инструменты проверки | Явный `benchmark --max-rub` включает и проверяет ограничение собственного запуска до upload; безопасно восстанавливает предыдущий флаг. Неопределённая работа остаётся fail-closed. `resource_check` изолирован от .env/ключа/облака и использует отдельный каталог запуска. |

Технические пределы ответа (STT 4 MiB, summary 512 KiB, общий summary request до 60 000 символов) ограничивают память и размер данных. **Внутренние денежные ограничения приложения остаются выключенными**: `local_cost_limits_enabled=false`. Они не включались в рабочей конфигурации во время исправлений. Месячные настройки аккаунта Polza не менялись.
