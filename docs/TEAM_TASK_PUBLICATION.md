# Secretary → Vikunja: контракт публикации T5

Это контракт локальной интеграции. Ручная приёмка, внешний адрес, MAX и эксплуатация 24/7 проверяются отдельно в T6–T13. Состояние выполненных проверок хранится в `TEAM_IMPLEMENTATION_STATUS.md`.

## Выбор и подтверждение

Подтверждение ответственного в итогах не отправляет задачу команде. В разделе задач владелец отдельно выбирает пункты, готовит предпросмотр и подтверждает его. Сервер берёт текст, цитату и ссылки из сохранённого источника. Дата задаётся явно с часовым поясом `Europe/Moscow`; «Без срока» — отдельное подтверждённое решение. Фраза «к пятнице» сама по себе не является календарной датой.

Участник встречи связан с аккаунтом только через `person_profile_id → TeamMember.id`. Имя и похожий голос не заменяют эту связь. Для гостя без профиля требуется явный выбор действующего участника проекта. Неоднозначную или отсутствующую связь известного профиля сначала исправляют в настройках команды.

`PublicationCandidate.eligible` означает свежий валидный источник и подтверждённое назначение. Незаполненные параметры публикации возвращаются отдельными `reason_codes`; пока они не разрешены, сервер не выдаёт готовый `preview`.

## Идентификаторы и квитанции

Batch `operation_id` обозначает одно подтверждение предпросмотра. Каждый action получает свой publication UUID по `(meeting_id, transcript_version, summary_version, action_id, destination_project_id)`. Изменение assignment revision не меняет этот UUID. Для намеренного создания отдельной задачи требуется явное решение `create_separate` и сохранённый UUID этого решения.

Для новой версии итогов совпадение источника вызывает выбор владельца: `link` связывает с существующей карточкой через проверку чтением; `propose_update` добавляет предложение в комментарий; `create_separate` создаёт отдельную карточку. Автоматической замены ответственного, срока или выполненного результата нет. Предложение и связывание имеют собственные подписи состояния в UI.

`accepted/queued` означает принятие в очередь. «Опубликовано» допускается только после `applied`, проверенного чтения внешней карточки, совпадающего task ID, проекта и `verified_at`. Квитанция batch неизменна; состояние каждого пункта читается отдельно. Изменившийся источник обозначается `source_stale`; после исполнения — `correction_required`.

## Локальный API

Все маршруты наследуют localhost Host/Origin и `X-Secretary-Token` для изменений:

- `GET /api/v1/meetings/{meeting_id}/task-publications/context` — текущие источники и доступные получатели.
- `POST .../task-publications/preview` — выбранные IDs и явные параметры.
- `POST .../task-publications` — точный сохранённый preview/hash и batch operation ID.
- `GET .../task-publications` — история квитанций после перезагрузки страницы.
- `GET .../task-publications/{operation_id}` — квитанция конкретного подтверждения.

Без конфигурации команды API возвращает `503 team_publication_not_configured`. Конструктор `create_app(..., task_publications_factory=...)` предоставляет явную точку подключения для изолированного runtime T6. Автор команды задаётся сервером; браузер не выбирает свой уровень доступа.

## Сохранение и доставка

Source CAS, immutable подтверждение и outbox записываются в одной `BEGIN IMMEDIATE` транзакции Secretary DB. Проверяются текущие версии transcript/summary, assignment/roster/attribution revisions и `current_context_hash`; перед отправкой проверка повторяется. Source DB и Team DB сохраняют отдельные назначения и историю; `summary_publications` облачного worker не переиспользуется.

Перед единственным POST очередь сохраняет `dispatch_started` и hash ожидаемой Gateway-команды. При потере ответа, timeout, сбое процесса или истечении lease дальнейшие обращения — только GET по тому же delivery operation ID. `404` после отправки не доказывает отсутствие принятия. Неизвестный результат сохраняется для сверки; новое создание автоматически не выполняется.

Internal Gateway использует отдельный `X-Secretary-Service-Secret`, действующего owner и проверку реального loopback peer. Он принимает только publication envelope и чтение его квитанции. Публичный proxy обязан исключить `/internal/*`, а сервер запускается с `proxy_headers=False`; заголовки forwarding не устанавливают доверие.

Секреты, локальные пути аудио и сырые записи не входят в preview или описание карточки. Код T5 не выполняет платных запросов Polza. Общий месячный лимит 3000 ₽ остаётся контрактом T2 для последующей голосовой интеграции.

## Неизвестный внешний адрес

При подготовке T6/T12 проверить домен, внешний IP/CGNAT, возможность HTTPS и доступ с мобильной сети. Если входящие подключения недоступны, сначала выбрать согласованный способ защищённого доступа. Текущий Secretary API целиком наружу не проксируется. Наличие ИП не подтверждает регистрацию и действующий доступ к боту MAX.
